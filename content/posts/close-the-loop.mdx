## Introduction

I'll try to keep this short, hopefully by letting the above skill do the talking.

LLMs already know how to close the loop when building software from scratch... because, by some standard, this is nothing new. How else do you think pre-LLM engineers figured out why prod was failing? Did they have some magical crystal ball whispering in their ear? Well, kinda, but not literally, and much less so with the whispering part. 

## A very boring example: logs

Before LLMs, an engineer would ship code, see a pager, open Datadog, tail logs, check a trace, form a theory, add a metric, reproduce locally, write a test, patch the bug, deploy, then watch the dashboard until the line went flat again. That's closing the loop. The system produced feedback, the engineer observed it, changed the system, then checked whether reality agreed.

But the loop was mostly human-paced. The logs did not inject themselves into the engineer's brain. The dashboard did not block their next though. The test failure did not automatically rewrite their plan unless they chose to run the test, read it, understand it, and care.

Agents are quite different. Agents are mechanizable.
